# План сетевого режима LIFE TO LIVE

Статус: согласованная концепция для будущей разработки. Пока основная игра и её механики создаются отдельно.

## Общая идея

- На ПК будет отдельный режим **«Сетевая игра»**.
- Одиночная игра и локальные сохранения продолжают работать независимо.
- На телефонах пока остаётся локальная одиночная игра.
- Клиент игры размещается на GitHub Pages.
- Игровой сервер и база данных размещаются на VPS.
- Каждый игрок открывает для друзей **собственный существующий мир**, а не создаёт отдельный постоянный сервер.

## Предлагаемое меню

```text
Играть
├── Одиночная игра
└── Сетевая игра
    ├── Открыть свой мир
    │   ├── Только по коду
    │   ├── Для друзей
    │   └── Публичный
    ├── Найти мир
    ├── Войти по коду
    └── Рекорды
```

В интерфейсе лучше использовать понятные игроку формулировки **«Открыть свой мир»** и **«Пригласить друзей»**, а не техническое **«Создать сервер»**.

## Как работает мир

- Мир и его сохранение принадлежат владельцу.
- Владелец открывает мир для сетевой игры.
- VPS создаёт временную комнату и выдаёт код приглашения.
- Другой игрок находит комнату в списке либо входит по коду.
- Все разрешённые изменения сохраняются в мире владельца.
- Для первой версии вход возможен только тогда, когда владелец находится в игре.
- Когда владелец выходит, мир сохраняется, остальные участники отключаются, а комната закрывается.

## Игроки и персонажи

- У каждого игрока есть постоянный уникальный идентификатор, не зависящий от отображаемого имени.
- Игрок выбирает имя персонажа.
- Имя отображается над головой персонажа.
- Собственный персонаж должен визуально отличаться цветом, контуром или значком.
- Имена ограничиваются по длине и проверяются перед показом.
- Положение, направление, анимации и игровые действия других персонажей синхронизируются через сервер.
- Движение удалённых игроков сглаживается, чтобы задержка сети не вызывала рывков.

## Комнаты и подключение

- Создание публичной или закрытой комнаты.
- Название комнаты.
- Код приглашения.
- Необязательный пароль.
- Ограничение количества игроков.
- Список доступных миров с количеством участников.
- Вход по коду комнаты.
- Понятные сообщения при ошибке подключения.
- Обработка временного разрыва связи и переподключения.
- Проверка совместимости версий игры.

## Сохранения

Данные необходимо разделить на четыре части:

1. **Профиль игрока** — уникальный ID, имя, внешний вид, личная статистика и достижения.
2. **Сохранение мира** — карта, объекты, ресурсы и общий прогресс мира.
3. **Сетевая сессия** — владелец, список участников, код комнаты и права доступа.
4. **Рекорды** — результаты, проверенные и сохранённые сервером.

Для первой версии полноценная регистрация не обязательна. Игра может создать постоянный ID при первом запуске. Аккаунты понадобятся позднее, если потребуется перенос прогресса между устройствами.

## Права гостей

Перед реализацией необходимо окончательно определить:

- может ли гость строить и разрушать объекты;
- может ли брать предметы из хранилищ;
- может ли тратить общие ресурсы;
- сохраняет ли найденные предметы после выхода;
- может ли приглашать других игроков;
- какие действия доступны только владельцу мира.

На сервере должна быть система прав, чтобы гость не мог выполнить запрещённое действие изменённым клиентом.

## Рекорды

- Личная статистика игрока.
- Глобальная таблица рекордов.
- При необходимости — недельные рекорды и рекорды конкретного мира.
- Результаты рассчитываются или проверяются на VPS.
- Клиент не может самостоятельно записать себе очки, деньги или достижение.

## Техническая схема

```text
GitHub Pages: клиент игры
        │ HTTPS / WSS
        ▼
VPS: комнаты, синхронизация и проверка действий
        │
        ▼
PostgreSQL: профили, миры, сохранения и рекорды
```

- Клиент размещается на GitHub Pages.
- Серверная часть постоянно работает на VPS.
- Для VPS желательно использовать отдельный домен или поддомен и защищённое соединение `wss://`.
- Сервер принимает запросы только от разрешённых адресов клиента.
- Секреты, ключи и важная игровая логика не размещаются в клиенте GitHub Pages.
- Деньги, инвентарь, прогресс и рекорды подтверждаются сервером.

## VPS и обязательная проверка развёртывания

- Адрес VPS: `213.139.209.107`.
- Системный пользователь: `root`.
- Пароли, приватные ключи и другие секреты в репозитории не сохраняются.
- Перед первым рабочим развёртыванием необходимо сменить пароль, настроить вход по SSH-ключу и по возможности запретить вход `root` по паролю.
- После каждого изменения сетевой или серверной части выполняется развёртывание актуальной версии на VPS.
- После каждого развёртывания обязательно проверяются: доступность сервера, защищённое соединение клиента, создание комнаты, подключение второго игрока, синхронизация, переподключение, сохранение мира и запись рекордов.
- После проверки просматриваются серверные журналы на наличие ошибок.
- Неудачное развёртывание не считается завершённым: сервер возвращается к последней рабочей версии либо исправляется до прохождения проверок.

## Порядок будущей разработки

1. Добавить на ПК отдельный пункт «Сетевая игра».
2. Поднять сервер на VPS и подключить к нему клиент.
3. Реализовать открытие своего мира и подключение второго игрока.
4. Отобразить персонажей и имена над головами.
5. Добавить плавную синхронизацию движения и анимаций.
6. Синхронизировать игровые действия и состояние мира.
7. Добавить права гостей.
8. Реализовать сохранение мира, выход владельца и переподключение.
9. Добавить список миров, закрытые комнаты и вход по коду.
10. Добавить серверную статистику и таблицу рекордов.
11. Провести проверку защиты и нагрузочное тестирование.

## Решения, которые уже приняты

- Используем GitHub Pages вместе с VPS.
- Сетевая игра является отдельным режимом на ПК.
- Игрок приглашает товарищей в собственный мир.
- Мир принадлежит владельцу и сохраняется у него/на сервере как его мир.
- В первой версии комната работает только в присутствии владельца.
- У персонажей показываются имена над головами.
- Будут поиск комнат, создание комнаты, вход по коду и рекорды игроков.
